# Excel Foundations: Reliable Workbooks and Modern Formulas

## Excel as a model, not a collection of cells

A spreadsheet can produce the correct answer today and still be a poor model.

A reliable Excel workbook should do three things:

1. produce the correct result;
2. remain correct when data or assumptions change;
3. allow another analyst to understand and verify the calculation path.

A visible Excel error is often less dangerous than a plausible but incorrect number. If Excel displays `#VALUE!`, the problem is obvious. If a total silently excludes one row, the number may look reasonable and be copied into a report.

Professional spreadsheet design is therefore about reliability, traceability, and maintainability — not only about obtaining a number.

```quiz
question: Which statement best describes a reliable Excel model?
A: It produces a value without displaying an error.
B: It remains correct when inputs change and its logic can be traced.
C: It uses only one worksheet.
D: It contains no formulas longer than one line.
correct: B
explanation: A reliable workbook must remain correct when inputs change and allow its logic to be inspected and verified.
```

## Workbook architecture

A robust analytical workbook normally separates four logical layers.

### Data

The Data layer contains information from external sources: exports, transaction registers, invoices, measurements, operational records, or system extracts.

### Assumptions

The Assumptions layer contains controlled parameters such as tax rates, exchange rates, thresholds, targets, growth rates, or scenario inputs.

If a business parameter is expected to change, it should normally exist once in a controlled location rather than being repeated as a hard-coded number inside formulas.

### Calculations

The Calculations layer transforms source data and assumptions into analytical outputs.

Business logic should be consistent and easy to trace.

### Presentation

The Presentation layer contains KPI blocks, reports, charts, dashboards, and other outputs intended for the final user.

Presentation should display results rather than hide critical calculation logic.

A useful rule is:

> If a numeric value represents a controllable assumption, do not hard-code it repeatedly inside formulas.

Instead of:

```excel
=Revenue*15%
```

use a reference to the controlled assumption:

```excel
=Revenue*RentRate
```

## Excel Tables and structured references

Convert growing datasets to Excel Tables with `Ctrl+T`.

Tables:

- expand when new rows are added;
- propagate formulas;
- preserve consistent formatting;
- support structured references;
- integrate well with PivotTables, Power Query, and the Data Model.

Instead of:

```excel
=SUM(F2:F5000)
```

use:

```excel
=SUM(Sales[Revenue])
```

The second formula expresses the business meaning of the calculation rather than an accidental worksheet coordinate.

Inside a Table, `@` refers to the current row:

```excel
=[@Revenue]-[@Cost]
```

This can be read as “current-row revenue minus current-row cost.”

```quiz
question: Why is =SUM(Sales[Revenue]) generally more robust than =SUM(F2:F5000)?
A: It always calculates faster.
B: It converts Revenue to text.
C: The structured reference follows the Excel Table as rows are added.
D: It prevents users from changing the data.
correct: C
explanation: Structured references follow the Table and are less dependent on fixed worksheet coordinates.
```

## Relative, absolute, and mixed references

A relative reference changes when a formula is copied:

```excel
A1
```

An absolute reference stays fixed:

```excel
$A$1
```

A mixed reference fixes only the row or the column:

```excel
$A1
```

```excel
A$1
```

Suppose revenue is stored in `D2` and the tax rate is stored in `H2`.

A formula such as:

```excel
=D2*$H$2
```

allows the revenue reference to move when copied down while keeping the tax-rate reference fixed.

Important assumptions can also be assigned meaningful names such as:

- `TaxRate`
- `ExchangeRate`
- `ReportingDate`
- `TargetMargin`

Names should describe business meaning.

## Conditional logic: IF, IFS, and error handling

The basic pattern is:

```excel
IF(condition, value_if_true, value_if_false)
```

Example:

```excel
=IF([@Margin]>=0,"Profit","Loss")
```

For several conditions, `IFS` may be easier to read than deeply nested `IF` functions.

However, a very long nested formula often means that a business rule should be represented as a lookup table instead.

### Error handling versus error suppression

`IFERROR` can be useful when an expected exceptional condition is understood.

For example:

```excel
=IFERROR(A2/B2,0)
```

may be reasonable when a zero denominator has a defined business meaning.

But if the denominator is zero because required source data is missing, replacing the error with zero hides a data-quality problem.

Do not use error handling merely to make warning values disappear.

## Conditional aggregation

Core criteria-based aggregation functions include:

- `SUMIFS`
- `COUNTIFS`
- `AVERAGEIFS`

Example:

```excel
=SUMIFS(Sales[Revenue],Sales[Region],"North")
```

With multiple conditions:

```excel
=SUMIFS(Sales[Revenue],Sales[Region],"North",Sales[Category],"A")
```

Example with `COUNTIFS`:

```excel
=COUNTIFS(Sales[Region],"North",Sales[Revenue],">10000")
```

Use `SUMPRODUCT` when the condition itself requires calculation or when a weighted calculation is required.

Weighted average:

```excel
=SUMPRODUCT(Price,Quantity)/SUM(Quantity)
```

```quiz
question: Which function is the most direct choice for summing Revenue only for rows where Region equals North?
A: SUMIFS
B: UNIQUE
C: XLOOKUP
D: LET
correct: A
explanation: SUMIFS is designed for conditional aggregation and directly expresses the criterion-based sum.
```

## Lookup logic: XLOOKUP and INDEX/MATCH

Lookup formulas connect one dataset to another.

Suppose Sales contains `Product ID`, while Products contains:

- Product ID;
- Product Name;
- Category;
- Manager.

A modern lookup can be written as:

```excel
=XLOOKUP([@ProductID],Products[ProductID],Products[Category])
```

This explicitly identifies:

1. the value being searched for;
2. the lookup array;
3. the return array.

Before trusting a lookup, verify the key.

If `Product ID` is expected to be unique but occurs twice in the reference table, the analytical relationship is ambiguous.

A formula cannot repair a defective key structure.

`INDEX/MATCH` remains important because it appears in many existing workbooks:

```excel
=INDEX(Products[Category],MATCH(A2,Products[ProductID],0))
```

`MATCH` finds the position and `INDEX` returns the value from that position.

```quiz
question: What should be checked before relying on Product ID as a lookup key?
A: Whether the worksheet uses gridlines.
B: Whether Product ID has the expected uniqueness in the reference table.
C: Whether the workbook uses dark mode.
D: Whether the formula contains an absolute reference.
correct: B
explanation: Duplicate keys can make lookup results ambiguous and can later break expected relationships in analytical models.
```

## Dynamic arrays: UNIQUE, FILTER, and SORT

Modern Excel formulas can return multiple cells.

```excel
=UNIQUE(Sales[Region])
```

returns a dynamic list of distinct regions.

Functions can be combined:

```excel
=SORT(UNIQUE(Sales[Region]))
```

`FILTER` returns only rows that satisfy a condition:

```excel
=FILTER(Sales,Sales[Region]="North")
```

Multiple conditions can be combined:

```excel
=FILTER(Sales,(Sales[Region]="North")*(Sales[Revenue]>10000))
```

The spill operator `#` refers to the complete dynamic output.

If `H2` contains a spilling formula, then:

```excel
H2#
```

means the complete current spill range generated from `H2`.

A `#SPILL!` error usually means that Excel cannot place the array because required cells are blocked.

A useful rule is:

> Excel Tables are excellent for structured input. Dynamic arrays are excellent for dynamic analytical output.

## LET and formula readability

`LET` allows meaningful local variables to be defined inside a formula.

Conceptually:

```excel
=LET(name1,value1,name2,value2,final_expression)
```

For example, a complex margin formula can define:

- revenue;
- cost;
- profit;
- margin;

and use those names in the final expression.

This improves readability and can avoid repeating expensive calculations.

Use `LET` when it makes complex logic easier to understand. Do not add it to simple formulas unnecessarily.

## Calculation mode and auditability

Excel builds a dependency graph between formulas.

Normally the workbook uses automatic calculation mode. In manual calculation mode, inputs can change while formula results remain stale.

Useful recalculation commands include:

- `F9` — recalculate changed formulas and dependencies;
- `Shift+F9` — recalculate the active worksheet;
- `Ctrl+Alt+F9` — force a full recalculation.

Some functions are volatile:

- `TODAY`
- `NOW`
- `RAND`
- `RANDBETWEEN`
- `OFFSET`
- `INDIRECT`

Volatile functions are not automatically wrong, but many of them in large dependency chains can reduce performance and transparency.

When diagnosing a workbook:

1. check calculation mode;
2. identify volatile formulas;
3. inspect dependencies;
4. look for repeated expensive calculations;
5. then decide what should be rewritten.

```quiz
question: Why can manual calculation mode be risky?
A: Excel may display stale calculated values after inputs change.
B: Excel Tables cannot be created.
C: XLOOKUP no longer supports exact match.
D: Power Query deletes the source files.
correct: A
explanation: Manual calculation can leave outputs unchanged after inputs are edited, creating internally inconsistent but apparently valid workbooks.
```
