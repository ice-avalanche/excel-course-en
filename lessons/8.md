# Final Assessment Preparation

## Purpose of this session

This session is designed to prepare you for the final assessment.

No new material is introduced here.

Use this page to review the complete workflow covered in Lessons 1–7 and verify that you can apply the main tools without relying on step-by-step instructions.

The final assessment may require several techniques to be combined in one task.

## 1. Reliable workbook design

Make sure you can:

- separate Data, Assumptions, Calculations, and Presentation logically;
- identify hard-coded business assumptions;
- replace fragile fixed ranges with Excel Tables where appropriate;
- use structured references;
- distinguish relative, absolute, and mixed references;
- identify formulas that return plausible but incorrect results;
- check calculation mode;
- recognize when volatile functions may affect performance or auditability.

You should be able to explain why a workbook can contain no visible Excel errors and still be analytically unreliable.

## 2. Modern Excel formulas

Review the following functions and concepts:

```excel
=SUMIFS(...)
```

```excel
=COUNTIFS(...)
```

```excel
=AVERAGEIFS(...)
```

```excel

```

```excel

```

```excel

```

```excel
=FILTER(...)
```

```excel

```

Make sure you understand:

- when a lookup key should be unique;
- how dynamic arrays spill;
- what causes `#SPILL!`;
- when `IFERROR` is appropriate;
- when error suppression may hide a data-quality problem.

## 3. Power Query

Make sure you can build a repeatable transformation pipeline.

You should be able to:

- connect to Excel, CSV, and folder-based sources;
- inspect and correct data types;
- remove unnecessary rows and columns;
- rename columns;
- clean text with Trim and Clean;
- replace values;
- split columns;
- remove duplicates using an appropriate business key;
- create calculated columns;
- Append similar datasets;
- Merge datasets using a key;
- distinguish Left Outer Join from Inner Join;
- preserve unmatched records when they are important for validation;
- Unpivot wide tables;
- refresh the full process;
- validate row counts, date ranges, nulls, and unmatched keys.

Remember:

> A successful refresh does not automatically mean that the result is correct.

## 4. Data Model, PivotTables, Power Pivot, and DAX

Review the difference between:

- fact tables;
- dimension tables;
- calculated columns;
- measures.

Make sure you understand:

- table grain;
- one-to-many relationships;
- key uniqueness;
- star-schema logic;
- PivotTable aggregation;
- filter context;
- how slicers affect measures.

Be ready to use or interpret measures such as:

```text
Revenue := SUM(Sales[Revenue])
```

```text
Gross Profit := [Revenue] - [Cost]
```

```text
Margin % := DIVIDE([Gross Profit], [Revenue])
```

Also review the role of `CALCULATE` and why `DIVIDE` is often preferable to direct division in reusable DAX measures.

## 5. What-If Analysis and model validation

Review:

- Scenario analysis;
- one-variable Data Tables;
- two-variable Data Tables;
- Goal Seek;
- model validation.

You should understand the difference between:

- changing assumptions to observe model behavior;
- solving for one input required to reach a target;
- validating whether a model is structurally and analytically correct.

Before using a model for decisions, check:

- assumptions;
- units;
- signs;
- totals;
- boundary values;
- calculation dependencies;
- consistency between detailed and aggregated results.

## 6. Data analysis, statistics, and forecasting

Review:

- count, mean, median, minimum, maximum;
- percentiles;
- variance and standard deviation;
- distributions and outliers;
- correlation;
- rolling averages;
- trends;
- linear regression;
- forecasting;
- forecast-error evaluation.

Make sure you understand that:

- correlation does not prove causation;
- outliers should be investigated before removal;
- a forecasting model should be evaluated on data not used to fit it;
- a forecast is incomplete without an error measure.

## 7. VBA and Excel automation

Make sure you understand when VBA is appropriate.

Review:

- the Excel object model;
- Workbook;
- Worksheet;
- Range;
- variables;
- conditions;
- loops;
- Sub procedures;
- Functions;
- explicit object qualification;
- error handling.

You should be able to explain why Power Query, formulas, DAX, and VBA solve different automation problems.

Avoid broad error suppression such as uncontrolled use of:

```text
On Error Resume Next
```

A robust macro should report failures clearly and restore application state when necessary.

## 8. Interactive dashboards and automated reporting

Review the purpose of:

- KPIs;
- PivotCharts;
- slicers;
- timelines;
- conditional formatting;
- visual hierarchy;
- refresh automation.

A dashboard should answer business questions rather than simply display available data.

Make sure you can:

- select a suitable chart for comparison, trend, composition, distribution, or relationship;
- connect slicers to the intended report objects;
- keep filter state visible;
- avoid unnecessary visual noise;
- structure information according to importance;
- verify that dashboard values reconcile with the underlying model.

## 9. End-to-end workflow

Be ready to work with the complete analytical chain:

**Source data → Power Query → Data Model / calculations → validation → dashboard → optional VBA automation**

For each layer, ask:

1. What is the input?
2. What transformation is being performed?
3. What assumptions are involved?
4. What can fail?
5. How can the result be validated?

The final assessment may combine several layers.

For example, you may need to:

- clean data in Power Query;
- connect it to reference data;
- build calculations;
- validate totals;
- create an analytical output;
- explain why your solution remains reliable when new data arrives.

## Final readiness checklist

Before starting the final assessment, verify that you can answer **Yes** to the following questions:

- Can I distinguish source data from assumptions and calculated outputs?
- Can I identify a fragile Excel formula?
- Can I use Excel Tables and structured references?
- Can I build lookup and conditional aggregation formulas?
- Can I work with dynamic arrays?
- Can I create a repeatable Power Query pipeline?
- Can I explain the difference between Append and Merge?
- Can I identify unmatched or duplicated keys?
- Can I explain fact and dimension tables?
- Can I distinguish calculated columns from measures?
- Can I explain filter context?
- Can I use What-If tools appropriately?
- Can I validate a model rather than simply trust its output?
- Can I interpret descriptive statistics and basic forecast results?
- Can I identify an appropriate use case for VBA?
- Can I design a dashboard around a business question?
- Can I trace an analytical result from source data to final output?

If any answer is **No**, return to the corresponding lesson before opening the final assessment.
